# FollowUp

実装中に見つけた不具合・エッジケース・見た目の修正・設計書の食い違いを記録する。その場では直さない(主ルートが止まる不具合を除く。AGENTS.md §0)。

- 形式: `- [ ] F-<連番> 内容 / 発見元タスク / 重大度(高・中・低)`
- 連番は追記順。完了したら `[*]` にする。
- 重大度: 高 = 主ルートの体験に影響する、中 = 主ルート外の機能が動かない、低 = 見た目・文言・エッジケース。
- 設計書の食い違いは「設計:」で始め、実装は契約書に合わせたことを書く。
