## 前提と決定事項

- 位置づけは「旅の同行者探し」。主顧客は自治体。 [決定、旧 design.md 1.2 ほか]
- 競技ルール: localhost 完結、外部API/DB/クラウドへの実行時依存なし、ダミーデータ使用、ログイン不要。 [決定、rule.md 3・6・7]
- 機能の柱は 18 件(02 章)。**窓口の提案であり、柱全体の採否はオーナー未確定(12 章 #5)。** 13〜18 の追加はオーナー決定に基づく。
- 利用者のロールは、旅行者・自治体・観光事業オーナー・地元の担い手の 4 つ(01 章)。 [決定、判断 31]
- 観光事業オーナー向けの機能「需要見込みと提案」を追加する。概要は 01・02 章、詳細は [../feature/13-tourism-owner-insight.md](../feature/13-tourism-owner-insight.md)(作成中)。 [決定(追加する)、判断 31〜34]
- docs/design と docs/feature の関係: docs/design が「何を作るか・全体方針」、docs/feature が「モジュールごとにどう作るか」。モジュール間で共有する名前・署名・パス・値は契約書を正とする。docs/design と契約書が食い違う場合は docs/design を正とするが、契約書の第 12 章で求められた更新は本書に反映済み(2026-11-09)。

## 状態の凡例

- [決定]: 合意済み / [案]: 検討中の案 / [未決]: 決める必要がある / [要確認]: 事実確認が必要
- [事実]: 資料・コードで確認できたこと / [推定]: 推測(既存サイトはログイン前の静的解析のみ)
- 参照の書き方: 「契約書 X.Y」は契約書の節、「判断 N」は `.work/review.md` に記録したオーナー判断の論点番号(1〜34。日付はいずれも 2026-11-09)。契約書の [統一] は詳細設計で選んだ案で、本書では [案] として扱い、オーナー判断を経たものだけを [決定] とする。
