# 07 安全・セキュリティ・規制

## 目的
初対面の同行に伴うリスクと規制への対応方針、セキュリティ対策を定める。柱5〜8が中心。

## 含める内容
- 安全機能: プロフィール公開範囲(5)、通報・ブロック(6)、本人確認・18歳確認(7)、禁止表現の制御(8)
- 安全の運用(迷惑行為への対応、合流の安全)
- セキュリティ対策(入力検証、XSS、秘密情報の扱い)
- 規制の整理と個人情報の扱い

## 現時点で分かっていること

### 安全機能
- 設計原則: 承諾がそろうまで連絡先・本名を見せない。公開情報は利用者が選ぶ。 [決定、旧 design.md 6]
- 柱5: プロフィール項目ごとの公開設定。 [案]
- 柱6: 通報・ブロックをいつでも使える。 [案]
- 柱7: 競技はログイン不要のため本人確認・18歳確認は**モック**。確認結果のみ保持。 [決定(モック)]
- 柱8: 恋愛・異性交際を連想させる文言・入力欄、性別での絞り込みは設けない。名称・訴求も同様。グループ参加を基本にする。 [案、ideas.md 5.5 の工夫案]
- 合流は日中・公共の場所を推奨。 [案、F-5]

### 規制(出会い系サイト規制法) [推定。法的判断ではない]
- 届出制。条件は「面識のない異性との交際を希望する人の情報を公衆が閲覧できる状態にし、連絡できるようにする」。 [事実(公開資料の理解)、ideas.md 7.5。警察庁解釈基準での裏取りは未実施]
- 同行フロー(プロフィール公開、選択、成立後の連絡)は該当性が最も高い設計に近い。 [推定]
- 18歳未満を巻き込まない設計が必要。旅行業法、個人情報も別途確認。 [要確認]

### セキュリティ
- 認証情報を含むファイル(`.env*` 等)をコード・資料に含めない。 [決定、rule.md 7、AGENTS.md 5]
- 入力検証、出力のエスケープ、ダミーデータのみ使用。具体策は未作成。
