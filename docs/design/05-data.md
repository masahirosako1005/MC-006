# 05 データ設計

## 目的
アプリが扱うデータ(ダミーデータと追加データ)の構造と持ち方を定める。

## 含める内容
- データ一覧とエンティティ関係
- ダミーデータ(出所、生成方法、件数)
- 保存方法(ローカル)
- 個人を特定しない集計の定義

## 現時点で分かっていること

- テストデータの基本は競技提供データ。`sample-data/*.csv` から `app/src/data/seed.json` を生成する。 [事実、rule.md 3、AGENTS.md 1]
- sample-data にはユーザー情報が含まれる。設計書や資料には必要最小限しか転記しない。 [事実、AGENTS.md 5]
- 実在個人を識別できる情報は使わない。 [決定、rule.md 7]

### 追加データの候補(名称・項目は仮。scratch.md 3 より) [案]
| データ | 内容 | 柱 |
|---|---|---|
| 旅程(Trip) | グループ、行き先、日程、日程の幅、人数(2〜6)。単独利用者も 2人以上のグループとして扱う前提(待機中の1人は「募集中の人数1」の状態か、本人のみのグループか) | 2 |
| グループ(Group。旧 Party を置換) | グループID、名称、人数上限(2〜6)、行き先・日程(Trip を参照)、**公開設定(公開/非公開)**、**タグ(テーマ。複数)**、**公式枠フラグ**(自治体のおすすめプラン)、**幹事(作成者のダミーユーザーID)**、招待コード(ダミー。主に非公開グループ用)、作成日時。1対1は人数2のグループ | 2、3、12、13、17 |
| 参加申請(JoinRequest) | 申請ID、グループID、申請者(ダミーユーザーID)、ひとこと、**状態(申請中/承認/却下/取り下げ)**、申請日時、判断日時、判断者(幹事)、却下理由(持つかは未決、12章 #15)。承認でメンバーに追加する | 4、13 |
| メンバー(GroupMember) | グループID、ダミーユーザーID、状態(参加中/退会)、**役割(幹事/メンバー)**、参加日時、退会日時。参加前の状態は参加申請が持つため、「招待中/参加申請中」は持たない(招待コード経由も申請を経る前提。12章 #17) | 13 |
| グループの旅程・メモ(GroupPlan) | グループID、集合場所メモ、日程メモ、更新者、更新日時(全員が編集可) | 14 |
| グループチャット(GroupMessage) | グループID、送信者、本文(または定型文ID)、送信日時、通報状態。ローカルのダミーデータ | 15 |
| 費用メモ(ExpenseNote) | グループID、項目名、金額(メモ)、立て替えた人、分担するメンバー、メモ日時。**決済・送金状態は持たない** | 16 |
| グループ単位のスタンプ集計 | グループID、スポットID、スタンプ取得メンバー、取得日時。グループ全体の達成数は集計で出す | 9 |
| プロフィール(Profile) | 表示名、年代、一言、旅の目的、項目別の公開設定 | 5 |
| 希望(CompanionRequest)、成立(CompanionMatch) | 旧案の個人間の希望・承諾。グループ参加申請(JoinRequest)に統合する方向(申請者 → グループの幹事の承認)。統合の可否は未決 | 4 |
| メッセージ(Thread、Message) | 成立後の会話 | 4 |
| 通報・ブロック(Report、Block) | 内容、対応状況、ブロック関係 | 6 |
| 本人確認(Verification) | 確認結果のみ(モック) | 7 |
| 協力者(Host)、同行枠(HostSlot)、イベント | 日時、定員、申込 | 12 |
| スタンプ・記録 | 同行ラリーの履歴(個人の記録に加え、グループ単位の集計を持つ) | 9 |
| 集計 | 参加、成立、再訪(個人を特定しない) | 11 |

### グループのデータに関する決定と案
- 人数上限は 2〜6人。1対1は人数2のグループとして扱い、データ構造をグループに一本化する。 [決定、オーナー]
- 幹事制: グループには作成者が幹事として1人いる。幹事が参加申請を承認・却下する。それ以外のメンバーは対等。前回の「管理者なし」を更新した。 [決定、オーナー]
- 幹事に与える権限の範囲(除名、プラン編集、設定変更)と、幹事の退会・不在時の引き継ぎ(次の幹事の決め方)は未決。役割は「幹事/メンバー」の2値で持ち、権限の範囲が決まるまで承認以外の特権を実装しない。 [未決、12章 #13・#14]
- 公開設定は公開/非公開の2種類。公開グループだけが一覧(柱3、17)に載る。非公開は招待コードを知る人だけが申請できる。 [決定(種類)、扱いの詳細は未決 12章 #17]
- 一覧に出す項目は、グループの公開項目(行き先、日程、タグ、空き人数、公式枠フラグ)と、メンバー概要(人数、年代帯の分布などの集計。個人を特定しない)。メンバー概要の粒度は 07 章・12章 #16。 [決定(4項目)/案(粒度)]
- メモ・チャット・費用メモの更新は、参加中メンバーの全員が行える(幹事に限らない)。 [案]
- 費用メモは金額をメモとして持つだけ。決済・送金のデータは持たない。 [案]
- チャット・通知はローカルのダミーデータで表し、外部サービスに依存しない。 [案、rule.md 3・6]
- 人数が 2 になる前の「1人で募集中」の扱い(人数1のグループを許すか)。 [未決、要確認]
