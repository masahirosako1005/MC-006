# 05 データ設計

## 目的
アプリが扱うデータ(ダミーデータと追加データ)の構造と持ち方を定める。

## 含める内容
- データ一覧とエンティティ関係
- ダミーデータ(出所、生成方法、件数)
- 保存方法(ローカル)
- 個人を特定しない集計の定義

## 現時点で分かっていること

- テストデータの基本は競技提供データ。`sample-data/*.csv` から `app/src/data/seed.json` を生成する。 [事実、rule.md 3、AGENTS.md 1]
- sample-data にはユーザー情報が含まれる。設計書や資料には必要最小限しか転記しない。 [事実、AGENTS.md 5]
- 実在個人を識別できる情報は使わない。 [決定、rule.md 7]

### 追加データの候補(名称・項目は仮。scratch.md 3 より) [案]
| データ | 内容 | 柱 |
|---|---|---|
| 旅程(Trip) | 利用者、行き先、日程、日程の幅、人数 | 2 |
| グループ(Party) | 代表者、メンバー、人数 | 2 |
| プロフィール(Profile) | 表示名、年代、一言、旅の目的、項目別の公開設定 | 5 |
| 希望(CompanionRequest)、成立(CompanionMatch) | 送信側・受信側、状態(送信・承諾・断り・取り消し)、成立日時 | 4 |
| メッセージ(Thread、Message) | 成立後の会話 | 4 |
| 通報・ブロック(Report、Block) | 内容、対応状況、ブロック関係 | 6 |
| 本人確認(Verification) | 確認結果のみ(モック) | 7 |
| 協力者(Host)、同行枠(HostSlot)、イベント | 日時、定員、申込 | 12 |
| スタンプ・記録 | 同行ラリーの履歴 | 9 |
| 集計 | 参加、成立、再訪(個人を特定しない) | 11 |
