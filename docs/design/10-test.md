## 目的
主要ユースケースが最後まで動くこと、安全機能が意図どおり働くことを確認する。

## 含める内容
- 試験項目(柱ごと、画面ごと、状態遷移ごと)

- 完成の基準: README の手順で起動でき、デモが最初から最後まで通り、モック部分が画面上で分かる。 [案、output.md 4.5]
- 試験項目の例: 承諾前は連絡先が見えない、18歳未満(モック)は進めない、ブロック後は候補に出ない、禁止表現が画面に出ない、性別絞り込みがない。 [案]
- 実行条件の試験観点(柱18。骨子。判定はダミー日付を進めて行う): [案]
  - 最少人数に到達: 締切までに最少人数に達すると「最少人数到達」になり、締切後に辞退期間を経て「実行確定」になる。確定時に実際の人数と参加者の概要が通知される(個人が特定されない粒度)。
  - 未達で自動中止: 締切に最少人数に満たないと自動で「中止」になり、中止の通知が出る。人手の操作なしで遷移する。
  - 辞退で最少を割る: 辞退期間中の辞退で最少人数を割ったときの遷移(募集中に戻る/中止。12章 #21 の決定どおり)。辞退にペナルティの表示・記録がない。確定後の辞退の扱い。
  - 再企画: 中止したグループから再企画を作れ、元グループへの参照が残る。前回の参加者へ案内が通知され、再エントリー時に「最少人数でもOK」の同意が再度確認される。
  - 同意: 同意の確認なしでは(12章 #22 の決定に応じて)申請できない/条件付きになる。
  - 表示: 一覧とグループ詳細に最少人数・定員・現在人数と状態が正しく出る。1対1(定員2・最少2)でも成り立つ。定員到達時の表示。
  - 幹事の条件変更: 最少人数を上げる変更や締切の延長が、決めた範囲だけ許され、参加者に通知される。幹事の退会・不在時の実行条件(12章 #25)。
  - 状態の反映: 各状態が画面(バッジ、進行状況)と通知に反映され、「日付を進める」操作で遷移を確認できる。

### 自動試験
- 試験の基盤は Vitest。各モジュールは `node --test` を使わない。 [決定、判断 11]
- 実行は `app/` で `npm test`。設定は `vitest.config.ts`(00)。API の試験は共通の `callRoute`(変更系は `Content-Type: application/json` を付ける)で Route Handler を直接呼び、前提データは seed の ID 定数(状態ごとの見本 `GROUP_BY_STATUS` ほか)と試験専用の 900 番台の ID を使う。 [案、契約書 11.3]
- 優先する範囲は主ルート(グループ作成 → 一覧・検索 → 参加申請 → 承認 → 最少人数到達 → 締切 → 辞退期間 → 実行確定 → 実施 → 完了 → 自治体向け集計、中止 → 再企画の基本の流れ、必須 12 種の通知、安全の基本、招待コード)。同時操作の競合、レート制限の画面表示、不正値の網羅などの試験は「見送り」と印を付けて後回しにする。 [決定(主ルート優先、`.work/review.md` 12 章)/案(範囲、契約書 16 章)]
- 各モジュールの試験項目は docs/feature の各設計書にある。
