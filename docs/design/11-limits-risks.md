# 11 既知の制約・リスク・マイルストーン

## 目的
今回の実装の制約と、設計・運用上のリスクを明示する。

## 含める内容
- 既知の制約(モック範囲、ダミーデータ、未接続の外部機能)
- リスクと対策の方向
- マイルストーン(段階案との対応)

## 現時点で分かっていること

### 制約
- ログイン不要、外部API/DB/クラウド不可、ダミーデータのみ。 [決定、rule.md]
- 本人確認、チャット、通知、外部連携はモックまたは簡易実装。 [案]
- 既存サイトの情報はログイン前の静的解析に基づく推定を含む。 [事実]
- 詳細設計で既知の制約とした事項(2026-11-09): [決定(判断番号を付けたもの)/案(その他)]
  - CSP を設けない。インラインスクリプトの注入を防ぐ仕組みは React のエスケープと `dangerouslySetInnerHTML` の禁止だけ(判断 2)。
  - 招待コードの照合は試行回数に数えないため、総当たりへの耐性はコードの乱数の空間と有効期限だけに依る(判断 8)。
  - 状態はサーバーのメモリに持ち、再起動で初期データに戻る。JSON ファイルへの書き出しは見送る(契約書 16.2)。
  - デモの時計を後ろに戻しても、グループの状態は巻き戻さない(契約書 7.5)。
  - 集計の差分(期間や条件を変えた複数回の照会)による推測、メンバー概要の人数変化による推測、タイミング攻撃への対策は持たない(契約書 16.2)。
  - 幹事が不在になった場合の中止(遷移と理由)は型と遷移表に残すが、幹事は退会できないためデモでは発生しない(契約書 4.3)。
  - 個人特典は既存の特典機能(`/api/v2`)と連動しない(判断 21)。

### 見送りの範囲(2026-11-09)
- オーナー指示により、主ルートの動作を優先し、エッジケースの作り込みは見送ってよい。見送る内容(同時操作の競合ダイアログ、レート制限の画面表示、不正値への細かい応答、ブロック関係の細かい表示、通信失敗時の細かい表示、再企画の細部、差分による推測への対策、時計の後戻り・永続化、余力の機能、性能・網羅試験、方針の切替)は契約書 16.2。設計済みの記述は削除せず「見送り」と印を付ける。 [決定(方針、`.work/review.md` 12 章)/案(範囲、契約書 16 章)]

### リスク(旧 ideas.md、design.md 5 より) [推定]
| リスク | 対策の方向 |
|---|---|
| 規制の該当(同行フローは該当性が高い設計に近い) | 目的を「旅の同行者探し」に限定、文言・設計を安全側に。確認未了を明記 |
| 初対面の同行での事故・迷惑行為 | 本人確認、通報・ブロック、公共の場所での合流推奨 |
| 成立しない(同日程・同地方の人がいない) | 日程の幅、地元の同行枠、集合型イベント |
| 地元側の供給不足 | 自治体の事業と連携 |
| 識別の分断(キャンペーンごとにユーザーが別) | 横断機能が必要になれば識別の導入を検討 |
| 範囲が広すぎる | デモ優先順位に絞る |
| 位置づけの誤解(恋愛目的と受け取られる) | 名称・訴求を統一 |
