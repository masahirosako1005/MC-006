# デモシナリオ(3 分版・音声解説つき)

プレゼンターは**話さない**(解説は AI が音声で読み上げる)。画面操作も AI(Claude Code + chrome-devtools MCP)が行う。プレゼンターは「開始」の合図と、質疑対応を受け持つ。
操作の手順は [operation.md](operation.md)、台詞は [narration.md](narration.md)、読み上げは [speak.ps1](speak.ps1)。

## 1. 前提

| 項目 | 内容 |
| --- | --- |
| 想定聴衆 | 自治体の観光担当、観光事業者(宿・飲食・体験)のお客様 |
| 持ち時間 | **3 分(180 秒以内)** |
| サービス名・テーマ | **Kopa**(台詞では「こぱあ」)。観光だけにフォーカスせず、**地方都市と人、そして人と人をつなぐ**ことをテーマにしたサービスのデモ(N0 で説明) |
| 伝えること | 旅行者の「グループ旅行」の動きが、①旅行者の体験になり、②観光事業者の来訪見込みになり、③自治体の集計(個人を特定しない)になる |
| 画面 | スマホ幅(約 430px)のビューポート |
| 断り | これは**モック**。人物・地名(星凪諸島、虹帆町、鈴風高原など)・数値は**デモ用の架空データ**。冒頭の台詞 N0 で断る |

余った時間は質疑にあてる。

## 3. ストーリー(3 部)

1. **旅行者の体験**: 幹事がグループを作る(氏名や連絡先を入れる欄はない)。別の旅行者が、最少人数でも参加することに同意して申請し、幹事が承認する。人数が集まる。
2. **観光事業オーナー**: 過去の実績と未来の予定が一つの棒グラフに並ぶ。デモで作ったグループも、予定に入る。週を選ぶと年代の円グラフ。提案(席・部屋・体験の枠を用意)。
3. **自治体**: グループの作成数・申請数・実行確定率、地方別、流入元。5 件未満は「少数」と表示。

## 4. 下準備(本番前に済ませる)

本番の 3 分に入れないため、次を事前に行う(`/demo prep`。詳細は operation.md 第1章)。

- データ初期化(日付 2026-11-09、グループ番号 g-201 から)。
- 各画面を一度ずつ読み込み、サーバーとブラウザを温める。そのあと**もう一度初期化**して、デモ用データを汚さない。
- 音声テスト(短い発話)。
- 画面は「グループ作成」フォームを開いた状態で待機(u-001)。

## 5. 見せない・言及しない

トップ、一覧、スポット地図、実施中のタブ(旅程・チャット・費用・スタンプ)、デモ時計の進行、振り返り、通知。3 分に収まらないため省略する。必要なら operation.md の付録の追加章を使う。
未実装の機能(FollowUp で見送ったもの)には触れない。

## 6. 失敗時の代替

| 症状 | 対処 |
| --- | --- |
| 操作が止まった・要素が見つからない | AI は再取得して 1 回だけ再試行し、だめなら飛ばして次の部へ。台詞は止めない(operation.md 第6章) |
| 状態がずれた | 「デモを初期化」 → `/demo prep`。部 2・3 は初期化直後でも見せられる(部 1 のデモグループが予定に載らないだけ) |
| サーバー停止 | operation.md 第6章の再起動。その間、事前に撮ったスクリーンショットを見せる |
| 音が出ない | `/demo mute` で台詞を画面に出す。プレゼンターが読み上げる |
